# 底盘急停（E-Stop）

> 原则：急停必须同时满足两条
> 1. **不依赖控制程序**（视觉/脚本死了、卡了、SSH 断了都还能停）
> 2. **不能被控制程序覆盖**（按住之后，20 Hz 的 `drive()` 不能再把车开起来）

按可靠性从高到低，一共四层。前两层不依赖任何软件。

---

## 第 1 层：物理断电（首选，唯一真正的急停）

在小车电池到控制板的电源线上串一个**常闭按钮/开关**（蘑菇头急停按钮最顺手）。
按下 = 电机断电，1 秒内生效，与 MCU、Linux、网络全部无关。

- 成本：一个开关 + 两根线
- 缺点：断的是整车电，控制板也会重启

> 如果暂时没有开关：**直接拔电池插头**，效果一样。

---

## 第 2 层：板载 RESET 键（现在就能用，零成本）

按 VENTUNO Q 上的 RESET，MCU 重启：

- 固件 `chassis_v2_atomic` 上电第一件事就是 `hardStop()`（三路 1500 µs 中位）
- `Bridge.begin()` 之前还会先发 300 ms 中位帧，让底盘最后看到的状态是「停」
- 不依赖 Linux 侧状态

代价：复位后到 USB 重新枚举之间约 1 秒没有信号。所以要确认底盘在「无信号」时的行为（见文末待验证项）。

适用范围：程序跑飞、车不听话、来不及敲命令时，伸手按一下就行。

---

## 第 3 层：锁存式软件急停（`scripts/estop.py`）

```bash
python3 scripts/estop.py            # 锁存急停（立刻硬停，并拒绝后续运动指令）
python3 scripts/estop.py --status   # 看状态：latched / leased / out / wd_stops
python3 scripts/estop.py --arm      # 解除锁存，恢复可动
python3 scripts/estop.py --stop     # 只停，不锁存
```

机制：

- MCU 侧 `estop()` 置**锁存位**，`drive/forward/back/turn` 直接返回 `false`
- 所以即使视觉循环还在 20 Hz 猛发指令，车也保持不动
- 必须显式 `arm()` 才恢复

**运行环境限制（重要）**：`estop.py` 需要能访问 `/var/run/arduino-router.sock`
（`root:arduino-router`，0660）。二选一：

1. 在 App 容器里跑（容器内自带 `arduino.app_utils`，可直接访问 socket）；
2. 宿主机一次性加组：

```bash
sudo usermod -aG arduino-router $USER    # 之后必须重新登录
```

> 当前这台机器上：用户**不在** `arduino-router` 组，宿主机也没有 `arduino` python 包
> （它只在 App 容器镜像里）。所以宿主机直接跑 `estop.py` 会失败——先做上面第 2 步。

## 第 4 层：自动兜底（已经在固件和 `car.py` 里）

| 位置 | 机制 | 效果 |
|---|---|---|
| MCU | 租约 300 ms | 没有任何新指令 → **硬停**回中位（不走斜率） |
| MCU | `ping()` 不续租约 | Router 心跳不会把车续着跑 |
| Linux `car.py` | 目标 TTL 250 ms | 调用方停止刷新 → 自动下发 0 |
| Linux `car.py` | `keep()` 结束自动 `stop()` | 定时动作不会漏停 |

这两层是「忘了停」「程序崩了」的兜底，**不能替代**第 1、2 层。

## 待验证 / 待做

1. **【必须验证】无信号时底盘会不会停。**
   慢速行驶中拔掉三根信号线（或按 RESET），观察车是停、是保持、还是继续前进。
   结果决定第 2 层是否够用；如果「无信号 = 继续保持」，就必须加第 1 层（物理断电）。

   > **已知线索（2026-10-31）**：档位通道 D6 是**窗口式**而不是阈值式——
   > `1000` 前进、`1250` 不稳定、`1400–1600` 倒车、`2000` 又前进
   > （见 `docs/chassis_control_verified.md` 第 8 节）。
   > 也就是说 **档位浮空或越界可能被底盘解释成「前进」**。
   > 在实测排除之前，**按「无信号 ≠ 停」处理**，即第 2 层不能单独作为急停手段。

2. **【建议做】把物理按钮接到 MCU。**
   一个常开按钮接某个空闲 D 脚 + GND，固件里读它 → 触发 `rpc_estop()`。
   这样急停既不依赖 Linux，也不用断整车电，比 RESET 更温和。
3. **【建议做】机械止动。** `chassis_v2_atomic` 删掉了 `brake()`，`stop()` 只是 1500 中位（滑行）。
   34 秒剪切期间如果车蠕动会扯断果梗，见 `architecture_v2.md` §12.4。
4. 急停后的恢复流程固定为：`--status` 确认 `latched=1` → 排除原因 → `--arm` → 低速试动。
