## 1. 背景与动机

刀片已装到 J6 上，J6 从「可自由多圈旋转的腕轴」变成「不可随意转动的工艺轴」。

- 物理现状（2026-10-24 实测）：刀片处于**最大打开**姿态，作为剪切起始位。
- 目标语义：**此刻位置 = J6 的 0°**；`0° = 剪切起始（刀片全开）`，`-60° = 剪切末尾（刀片合拢）`；
  剪切完成后回到 `0°`。
- 现存隐患：驱动层 `dummyarm_hardware.cpp:303-306` 把 J6 恒锁到 `cutter_target_pos_`，
  该变量**无任何赋值点，恒为 `0.0 rad`**；而当前固件 J6 实测 `-215.87°`。
  于是 **任何一次 MoveIt 轨迹 / `!HOME` / `!RESET` / `safe_park_and_exit.sh`
  都会让 J6 空转 215.87°** —— 装刀后必须立即消除的隐患。

零位是该隐患的正解：零位后固件 0° == 刀片起始位，驱动层锁定、`!HOME`、`!RESET`
与人工操作语义全部自洽，刀片静止。

## 2. 目标与非目标

### 2.1 目标（本次交付）
1. J6 **永久零位**（写电机 EEPROM，掉电不丢）：任何上电使能后 `#GETJPOS` 的 J6 ≈ 0。
2. 剪切行程**只在剪切层**限制为 `[-60°, 0°]`；URDF / IK / MoveIt 侧保持 `±720°` 多圈能力。
3. 剪切工具闭环可控：`合刀(-60°)` → 到位校验 → `回位(0°)`，不再用固定 `sleep`。
4. 提供轻量 Jog 窗口：J1–J5 可拖动实时跟随，**J6 锁定不可拖**，仅「合刀 / 回位」两个按钮。
5. 文档与 git 完整记录，代码 / 文档 / 提交三者一致。

### 2.2 非目标
- 不改固件源码、不改机械结构、不重新做全轴标定。
- **不缩小** `URDF Joint6` 限位（笛卡尔 IK 需要多圈解空间）。
- 不做 ROS 侧剪切服务/接口（列为遗留技术债，见 §10）。
- 不做移动底盘、视觉、任务层改动。

## 4. 设计

### 4.1 J6 永久零位

**支持性探测（无副作用）**
```
发送  #OFFSET_J 99
期望  "error HOMEOFFSET MOTOR [99] is wrong"     → 命令存在
超时无回复                                        → 命令不存在，立即中止，不改任何状态
```
> 依据：`ascii_protocol.cpp` 中 `node` 仅在 `1..7` 时才真正下发 CAN，越界只回 error，不写 EEPROM。
> 本机实测（F12）回的是通用 `ok`，因此探测**只能排除"完全无回执"**的情况；
> 是否真正生效由零位后的读数判定（§4.1 第 4 步）。

**零位时序**
```
0) 前置：机械臂静止、刀片无人接触、ROS 侧全部停止（串口独占）
1) !START                                    → 期望 "Started ok"
2) #GETJPOS                                  → 记录 (j1..j5, j6_old)
3) 一次 write 内连发（避免控制环插入陈旧目标）：
       #OFFSET_J 6
       >j1,j2,j3,j4,j5,<ε>,1
   ε = 0.05°，方向 = 合刀方向（由 §4.2 确认结果决定符号）
   目的 A：零位后 REF 的 targetJoints 立刻对齐新坐标，杜绝「补转 215°」
   目的 B：目标与实测不相等，规避 F9 的 0/0 = NaN
   目的 C：ε 取合刀侧，避免顶到「最大打开」方向的机械限位
4) #GETJPOS（连续 3 次）                     → 期望 J6 ∈ [-0.5, +0.5]，且稳定
5) 失败处置：
   - 位移 ≤5°：判定命令未生效（固件静默忽略），仅报告，不改其他状态；
   - 位移 >5°：立即 !STOP 并人工介入。
```
**为什么必须同包连发**：控制环 200 Hz（F5），若两命令分两次 write，中间可能插入一次
「陈旧 targetJoints = j6_old」的下发；电机按绝对目标（F6）执行会补转 `|j6_old|`。

**成功判据**：J6 读数稳定在 0±0.5°；J1–J5 变化 ≤0.1°。
实现容差放宽到 1.5°：ε 目标与 `#OFFSET_J` 在 CAN 上可能竞争，ε 偶尔会作用在
新坐标系的反侧；只要读数落回 0 附近即视为零位成功。

**持久化确认（必须做）**：断电 → 重新上电 → `!START` → `#GETJPOS`。
- 若 J6 仍 ≈ 0（本次实测约 -0.3°~0.0°）→ EEPROM 已保存；
- 若 J6 回到 ≈ 当前值 − 原读数（本次约 -1.4°）→ 偏移未保存，需改用软件偏移兜底。

> **2026-10-24 实测结论（重要）**：本机固件 `#OFFSET_J` **不生效**。
> 第二次在 J6=49.74° 尝试归零时，设备只是朝 `-0.2°` 目标走了 6.70° 就被保护中止，
> 读数并未归零 —— 证明该命令被静默忽略（通用 `ok` 即兜底）。
> 早期 A2/A3 判定的"通过"是误判：读数变化其实只是"被驱到目标值"，
> 而 `!START` 之后的读数又恰好等于固件默认 `REST_POSE`（驱动使能需要 1~3 s 才刷新反馈）。
> **正式方案改为 §4.5 软件零点。**

### 4.2 剪切行程与方向确认

- 方向确认（一次性）：从零点执行 `-3°`，人眼确认刀片是**合拢**方向。
  - 若 `-3°` 合拢 → 约定成立：`-60°` = 合刀到底，`0°` = 全开。
  - 若相反 → 全项目符号取反（`+60°` 为合刀），并在本节记录确认日期与结论。
  - **2026-10-24 实测确认**：从 0° 下发 `-3.00°`，J6 实际走到 `-3.00°`（未被全开限位挡住），
    说明负方向即合刀方向；随后回位到 `0.00°`。约定成立：`-60°` = 合刀到底。
- 剪切动作（闭环）：
```
合刀  >j1..j5, home-60, speed  → 轮询 #GETJPOS 至 |Δ|≤0.2° 或超时 15 s
回位  >j1..j5, home,    speed  → 轮询到位
```
- 行程约束只在剪切层生效：`CUT_RANGE = (home-60, home)`；
  `dummyarm_link.JOINT_LIMITS[6]` **保持 ±720** 不变。
- 剪切期间**禁止**任何 ROS 轨迹：驱动层会把 J6 覆盖回 `cutter_target_pos_`（F2）。
  工具启动前检查无 active 轨迹 / 无 controller 正在执行，否则拒绝。

### 4.3 Jog 窗口（轻量版）

- 技术形态：单文件 `scripts/jog_gui.py`，tkinter，直连 REF 串口（不依赖 ROS 在线）。
- 布局：
  - J1–J5：滑条（范围取自 `JOINT_LIMITS`），拖动实时跟随；50 Hz 读、20 Hz 下发、限速 25 °/s。
  - J6：滑条**禁用**；显示「相对角 = 实测 − home」，配 `合刀(-60°)` / `回位(0°)` 按钮。
  - 顶部：`使能` `失能` `回 HOME (0,0,90,0,0,0)` `急停（空格）`。
  - 状态栏：串口、循环频率、J6 相对角、最近一次回执。
- 必守规则：
  1. **静止检测**：某周期目标与实测差 < 0.02° 则不发（同时规避 F9 的 NaN）。
  2. 下发前按 `JOINT_LIMITS` 夹紧；J6 目标强制夹在 `CUT_RANGE`。
  3. 串口被 ROS 占用 → 明确报错退出，不做静默重试。
  4. 关窗：保持当前姿态悬停（保持使能），不自动失能、不自动回位。
  5. `!STOP` 仅由急停按钮/空格触发，绝不隐式发送。
  6. 窗口启动**不自动使能**（遵守 `architecture.md` §8「上电不自动使能、不自动运动」），
     必须在界面点「使能」；使能瞬间把目标对齐实测，不产生突跳。
  7. 读数必须严格匹配 `ok x x x x x x` 七字段行，超时重试；**禁止用陈旧读数初始化目标**
     （v2 修复：首轮真机测试中出现过读数假死 + 使能瞬间用旧值下发，导致 J5 被带偏）。
  8. **堵转保护**：J6 目标与实测差 > 0.5° 且 1.5 s 内位移 < 0.15° → 判定卡滞，
     立即停止下发并把目标回持当前值，提示断电检查（2026-10-24 因螺丝过紧实测触发）。

### 4.5 软件零点（正式方案，替代固件 EEPROM）

- 配置文件：`config/j6_blade.json`
  ```json
  { "j6_home_deg": -0.02, "cut_span_deg": 60.0, "measured_at": "2026-10-24" }
  ```
  `j6_home_deg` = 刀片**全开（剪切起始）**时的 `#GETJPOS` J6 读数。
- 剪切区间 = `[j6_home_deg - cut_span_deg, j6_home_deg]`，`cut.py` / `jog_gui.py` 均从此文件读取。
- 重新测量的时机（**必须**）：重新装配刀片、松/紧联轴器、更换刀片、发生打滑之后。
  流程：刀片摆到全开 → `python3 scripts/zero_j6.py --measure` → 核对打印出的区间。
- 与固件 `!HOME` / `!RESET` 的关系：这两条命令的 J6 分量恒为 `0`。
  当 `j6_home_deg` 与 0 相差很大时，它们会让 J6 转动该差值；因此
  **优先使用 GUI 的「回 HOME / 回 REST」**（会显式带上 J6 目标），固件 `!HOME`/`!RESET` 仅在
  `|j6_home_deg| < 2°` 时可直接使用。
- 优点：不依赖固件、可随时重测、可回滚（改文件即可）；缺点：需要人工保证装配后重测。

### 4.4 安全联锁

| 场景 | 行为 |
|---|---|
| 零位失败 / 读数未归零 | 位移 ≤5° 仅报告（判定命令未生效）；位移 >5° 立即 `!STOP` |
| 剪切超时未到位 | 停发指令 + 报警，保持当前位置 |
| J6 相对角越出 `[-60, 0]` | 拒绝下发，报错 |
| 任一关节超固件区间 | 拒绝下发，打印实测与允许区间（沿用「夹紧 + 提示」策略） |
| 串口连续无回复 > 1 s | 停止下发并提示链路异常 |

## 8. 回滚方案

1. 把刀片摆回旧参考位（或任意已知参考位），执行一次 `#OFFSET_J 6` 重新定义零点；
2. 若固件不支持该命令：退回**软件偏移**（`cutter_target_pos_ = 实测 home`，
   同时禁用固件 `!HOME`，改由 ROS 侧回 HOME）；
3. 所有改动在 git 分支 `feat/j6-blade-home`，回滚 = `git revert`。

## 10. 遗留技术债

1. 驱动层只有「锁 J6 = 常量」，没有正式剪切接口 → 后续改为 ROS 服务/参数设置 `cutter_target_pos_`。
2. `cut.py` 直连串口，与 ros2_control 共用同一 tty → 后续并入 ros2_control 通道。
3. 控制器 `Joint6 goal = 6.28 rad` 是掩盖锁轴的补丁 → 零位稳定后可收紧至 0.10 rad。
4. `instant_tap.py` 的 J6 搜索边界仍为 ±12.56 rad → 收敛到 0 附近，避免 IK 给出绕圈解。
