**文档结构**（按"项目 → 技术层 → 问题条目"组织）：

### 第一部分：Linux 网络文件管理系统（C）
1. **架构与并发模型** — epoll 主循环 + 预创建线程池 + 任务队列（互斥锁/条件变量）的协作方式；为什么用 epoll 而非 select/poll；线程池线程数参数化
2. **协议设计** — `train_t`（data_len + buf[1000]）定长头帧协议如何解决 TCP 粘包/半包；**双连接模型**（命令连接 + 文件传输连接）的动机；`recvn/sendn` 处理半包
3. **认证与安全** — 注册/登录三步握手流程；`$6$` SHA-512 加盐 `crypt()`；token 二次登录如何防止伪造文件传输连接；SQL 拼接注入风险与改进
4. **文件传输三大特性** — 服务端 `sendfile()` vs 客户端 `splice()`（pipe 中转）零拷贝原理与区别；`lseek` 断点续传（为什么 splice 场景不能 append）；MD5 引用计数秒传（count 字段 + rm 时文件池删除条件）
5. **超时与运维** — 环形队列 30s 超时断开的实现原理；操作日志全量记录
6. **面试官爱挖的坑** — 全局 `username` 跨线程共享、`chdir()` 全局进程状态、MySQL 每次查询建连（无连接池）、`count` 并发竞态、pNew 内存泄漏、`while(1);` 残留、`srand` 重复调用等，每项给出"如何承认 + 如何改进"

### 第二部分：智元灵犀 X2 考场巡检机器人（Python/ROS2）
1. **ROS2 通信架构** — Topic/Service 分工（速度/手部/音频 Topic vs 动作/TTS/焦点 Service）；BEST_EFFORT QoS 选型
2. **语音链路** — Vosk 离线 ASR + VAD 状态机（BEGIN/PROCESSING/END 组装音频缓冲）；开考指令语法识别（`use_command_grammar` + 常见误识别词兜底）；为什么用线程处理 ASR
3. **TTS 多级降级链** — Seed TTS（豆包，台湾腔 voice prompt）→ 系统 `PlayTts` → 跳过；音频焦点请求/释放；PCM 流式发布到 `/aima/hal/audio/playback`
4. **运动控制** — 输入源注册抢占（priority=40）；`McLocomotionVelocity` 周期发布实现移动；SetMcAction（LOCOMOTION_DEFAULT/STAND_DEFAULT）；预设动作（RAISE_HAND/POINT_HEAD）；手势 fallback（HandCommandArray）
5. **巡检状态机** — 等待开考语音 → 逐轮巡逻（前进→检测→转向 90°）→ 违规响应；信号优雅退出（SIGINT/SIGTERM 只置标志）
6. **LLM 对话** — DeepSeek/Qwen 调用 + 历史上下文 + 模板降级（responder.py）；台湾腔 system prompt
7. **坑与追问** — "检测结果"实为人工输入（`read_detected_item`），真实视觉检测的替代方案；`estimated_duration` 等待 vs 真实播放完成回调；service 超时与重试策略
