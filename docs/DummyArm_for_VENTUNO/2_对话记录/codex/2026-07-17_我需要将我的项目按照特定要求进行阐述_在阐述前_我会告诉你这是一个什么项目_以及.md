# 一、项目可行性阐述

## 1. 项目目标

本项目面向柑橘果园中重复频繁、劳动负担较重的低位采摘环节，研发一款能够在果园中自主移动、自主识别成熟柑橘并完成机械臂采摘和果实收集的移动机器人。

项目不追求覆盖整棵果树，而是将作业范围明确限定为**果实高度低于1米、处于机械臂可达空间且具备合理采摘条件的成熟柑橘**。机器人承担需要果农频繁弯腰完成的低位采摘任务，高位、严重遮挡及复杂枝叶区域仍由人工处理，从而形成“机器人负责低位重复劳动、人工负责复杂目标”的人机协同模式。

项目性能目标为：在真实果园条件下，对机器人判定为可采摘的低位成熟柑橘，实现不低于**80%的采摘成功率**。

建议将“采摘成功”统一定义为：机器人完成目标识别、定位、接近、果实分离，并将果实完整送入收集装置。测试时还应同时记录可采目标覆盖率、果实损伤率、单果采摘时间和连续作业时间，避免仅以成功率评价系统。

## 2. 核心亮点

第一，项目采用“聚焦低位、解决痛点”的产品定位。与试图覆盖整株果树的大型采摘机器人相比，本项目不盲目追求大臂展和全场景适应能力，而是针对果农弯腰频繁、低位作业疲劳度高的问题进行专项设计，有利于降低机械结构复杂度、整机尺寸和产品成本。

第二，项目已形成真实果园数据基础。团队已使用Intel RealSense D435i在浙江台州三门县采集超过14000张带深度信息的RGB-D柑橘图像，可用于成熟度识别、果实检测、遮挡分析和三维定位算法开发。相比仅使用公开二维图像数据，真实果园RGB-D数据更贴近最终应用环境。

第三，项目具备“感知—决策—执行—反馈”的具身智能闭环。机器人不是简单地识别果实或遥控机械臂，而是根据视觉和空间信息自主判断可采摘目标、规划移动与机械臂动作，并根据采摘结果调整后续任务。

第四，项目具有一定知识产权和硬件预研基础。目前已取得一项与采摘控制方法相关的发明专利；高精度、小型化Dummy Robot机械臂已完成调试；自主设计的末端执行器正在申请实用新型专利。上述成果降低了项目从概念验证进入系统集成阶段的风险。

第五，项目可以形成持续迭代的数据闭环。机器人在作业过程中可记录果实图像、深度、遮挡情况、机械臂轨迹和采摘结果，在取得果园授权并完成数据脱敏的前提下，用于模型迭代、失败案例分析以及后续模仿学习或强化学习研究。

## 3. 可行性依据

项目具备较好的可行性基础：

- 应用范围经过主动收缩，只处理1米以下且机械臂可达的目标，减少了机械臂行程、底盘稳定性和全树冠覆盖方面的难度。
- 已完成机械臂调试、末端执行器设计和真实果园数据采集，具备从单模块向整机系统集成的条件。
- YOLO类检测与分割模型、RGB-D定位、ROS 2导航、MoveIt 2机械臂规划等技术已经具备较成熟的工程基础。
- QCS8550和IQ-8275等端侧平台具备视觉模型推理、机器人规划和多传感器接入能力，能够支持机器人离线运行。

项目的主要技术风险包括强光下深度相机性能下降、枝叶遮挡、果实摆动、机械臂碰撞、复杂地面通行和末端采摘损伤。项目将通过深度置信度筛选、多帧融合、近距离二次定位、机械臂视觉伺服、碰撞检测和分阶段果园测试等方式逐步解决。

# 二、项目完整阐述

## 1. 设计理念

项目遵循四项设计理念：

- **聚焦低位：**只承担1米以下成熟柑橘采摘，避免过度追求全树覆盖。
- **人机协同：**机器人减少弯腰动作，不以完全取代人工为目标。
- **闭环作业：**每次采摘均包含感知、决策、执行和结果确认。
- **低成本小型化：**采用小型机械臂和窄体移动底盘，适应果树间距有限、枝叶密集的果园环境。

## 2. 应用场景和需求

项目主要应用于具有一定通行条件的柑橘果园，尤其是种植规模较大、低位果实较多、人工采摘成本较高的合作社和规模化果园。

机器人沿果树行间自主移动，在检测到低位成熟果实时停车或低速调整位置，选择可采目标，依次完成定位、采摘和收集。机器人不处理严重遮挡、超出机械臂工作空间或可能造成碰撞的果实，而是将其标记后留给人工处理。

## 3. 产品形态

项目最终形成一套由以下部分组成的低位柑橘采摘机器人：

- 窄体自主移动底盘；
- 小型高精度Dummy Robot机械臂；
- 自主设计的柑橘采摘末端执行器；
- RGB-D果实感知系统；
- 激光雷达、IMU、编码器等导航传感器；
- 端侧AI计算与实时控制平台；
- 果实收集装置；
- 任务管理、数据记录及远程运维软件。

## 4. 主要功能

机器人计划实现以下功能：

1. 果园行间自主导航和动态避障；
2. 低位柑橘检测、成熟度识别和三维定位；
3. 机械臂可达性、遮挡程度和碰撞风险判断；
4. 多目标采摘顺序规划；
5. 机械臂自主运动规划和近距离视觉修正；
6. 末端执行器完成果实分离和收集；
7. 采摘结果确认、失败重试和异常目标跳过；
8. 采摘数量、作业位置、图像和失败原因记录；
9. 急停、人员避让、通信异常保护和安全停车。

## 5. 市场与商业化路径

项目首要客户为大型柑橘合作社、规模化果园、农业社会化服务组织和农业科研示范基地。

商业化可分为三个阶段：

- **样机验证阶段：**与合作果园开展联合测试，按作业季进行示范应用。
- **产品导入阶段：**提供整机销售、季节性租赁和按作业量收费的采摘服务。
- **数据服务阶段：**在获得合法授权的前提下，提供果实成熟度分析、产量估计、作业报告和模型优化服务。

相比单纯售卖原始数据，更建议将数据商业模式表述为“提供经过授权的农业数据分析和模型服务”。原始果园数据涉及所有权、商业隐私和人员影像，直接售卖存在较高合规风险。

## 6. 所需支持

项目后续需要获得以下支持：

- 不同品种、树形和光照条件下的长期果园测试场地；

# 三、技术路线阐述

机器人总体作业流程为：

**任务下发 → 果园自主导航 → 低位果实搜索 → 成熟度识别与三维定位 → 可采摘性判断 → 底盘位置调整 → 机械臂规划 → 近距离视觉修正 → 采摘与收集 → 结果确认 → 前往下一目标**

## 1. 感知与环境建模

机器人使用Intel RealSense D435i获取RGB图像、深度图和惯性信息。

算法上不建议简单罗列“YOLO、Faster R-CNN、MobileNet、ResNet”。工程实现中可优先采用一个轻量化检测或实例分割模型，同时输出果实位置、成熟度类别和果实轮廓。实例分割比单纯矩形框更有利于处理果实重叠、枝叶遮挡和采摘点选择。

系统将检测结果与深度图对齐，对果实区域进行深度异常值剔除和多帧滤波，获得果实三维中心或适宜采摘点。通过相机标定、机械臂手眼标定和坐标变换，将相机坐标转换为机械臂基坐标，供后续运动规划使用。

D435i依赖主动红外深度技术，在强烈阳光下可能出现深度空洞或噪声。因此应设置深度置信度判断，并通过靠近后二次观测、多帧融合和RGB几何估计提高可靠性。条件允许时，可增加双目相机或其他室外深度传感器作为后续升级方案。

## 2. 自主导航与移动

底盘导航建议采用ROS 2和Nav2架构。激光雷达、轮式编码器、IMU和视觉信息经过融合后完成定位与地图构建。

全局路径规划可以使用A*或Hybrid A*，局部避障使用DWB、TEB或MPPI等局部规划方法，根据人员、树干、枝叶和临时障碍实时调整速度和行驶方向。

RRT更适合机械臂在高维关节空间中的避障规划，不建议将“A*或RRT动态导航”作为统一表述。移动底盘应采用“全局规划+局部避障”，机械臂则采用MoveIt 2结合OMPL、RRT-Connect等算法完成关节空间规划。

## 3. 采摘决策系统

采摘决策模块综合以下信息判断目标是否可采：

- 成熟度置信度；
- 果实高度和三维位置；
- 机械臂可达性；
- 枝叶遮挡程度；
- 末端执行器操作空间；
- 预计碰撞风险；
- 底盘是否需要进一步调整。

系统根据机械臂移动距离、目标可达性和遮挡风险对多个果实进行评分，优先采摘成功概率较高、运动代价较低的目标。

系统控制逻辑可采用行为树或分层状态机实现。现阶段不必强行使用大模型或强化学习；首先建立可解释、可复现的模块化闭环更加可靠。积累足够的成功与失败数据后，再使用模仿学习或强化学习优化目标排序、底盘停靠位置和机械臂轨迹。

## 4. 机械臂采摘控制

Dummy Robot机械臂接收目标位姿后，首先完成可达性检测和碰撞检查，再规划预抓取位姿和接近路径。

在机械臂接近果实时，系统使用视觉伺服进行二次位置修正，以减小相机深度误差、果实摆动和机械结构误差带来的影响。末端执行器按照既定的夹持、分离或切断方式完成采摘，并将果实送入收集装置。

采摘完成后，系统通过末端传感器、视觉变化或果实收集检测确认是否成功；失败时可进行有限次数的重新定位和重试，超过阈值后自动跳过并记录原因。

## 5. 端侧AI部署

模型训练在工作站或服务器完成，机器人端主要负责推理。训练后的模型经过剪枝、量化和硬件适配，转换为ONNX或高通平台支持的模型格式，在NPU上运行；CPU负责ROS 2节点、任务调度和路径规划，GPU可用于图像预处理和几何计算。

这种分工能够降低推理延迟和网络依赖，使机器人在果园无线网络不稳定时仍可独立工作。

## 6. 实施进度规划

- **前期预研——已完成：**采摘控制方法发明专利、Dummy Robot机械臂调试、末端执行器设计、14000余张RGB-D数据采集。

在机械臂接近果实时，系统使用视觉伺服进行二次位置修正，以减小相机深度误差、果实摆动和机械结构误差带来的影响。末端执行器按照既定的夹持、分离或切断方式完成采摘，并将果实送入收集装置。
采摘完成后，系统通过末端传感器、视觉变化或果实收集检测确认是否成功；失败时可进行有限次数的重新定位和重试，超过阈值后自动跳过并记录原因。
5. 端侧AI部署
模型训练在工作站或服务器完成，机器人端主要负责推理。训练后的模型经过剪枝、量化和硬件适配，转换为ONNX或高通平台支持的模型格式，在NPU上运行；CPU负责ROS 2节点、任务调度和路径规划，GPU可用于图像预处理和几何计算。
这种分工能够降低推理延迟和网络依赖，使机器人在果园无线网络不稳定时仍可独立工作。
