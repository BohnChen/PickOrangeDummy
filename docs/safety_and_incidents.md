# 事故史与安全约束（机械臂 + 整车供电，必读）

> 本文记录这台 Dummy 机械臂与整车供电的损坏历史、成因与由此确立的硬性操作约束。
> 任何新的控制代码/会话/操作者都必须先读本文。

## 1. 历史事故（主人陈述）

- 刚组装完成时，**J3 关节曾超出限位**，导致 **J4 与 J3 连接处崩坏**（结构损坏）。
- 主人随后**重新设置了机械臂的起始状态（标定）**，此后运行正常。
- 因此：本机软限位与标定零位是「校准后安全」的边界，**不得擅自扩大**；
  尤其 J3 的低位侧是历史损坏区。
- **装配教训（主人总结）**：新装/重装机械臂后，必须先对**每个关节逐一定位
  （setposition / 设起始零位）**、确认限位方向正确后再开始任何运动测试；
  不可直接跑整臂动作。

## 2. 2026-09-08 误命令事故（本会话）

- 原因：行为探针脚本参数顺序写错，误发大角度目标（J1→-74°、J2→0°、J3→90°），
  机械臂在低速下持续运动约 30~60s。
- 处置：`!STOP` 急停 → 冻结于 (J1=-43.8, J2=-29.8, J3=126.7) → 低速 (speed 3) 回 REST → 失能。
- 无结构损坏；教训：**任何非例行命令必须先经 `_check_limits` + 人眼复核格式**。

## 3. 硬性操作约束

1. J3 角度范围严格 **[35°, 180°]**（固件软限位=安全底线，禁止以任何方式绕过）
2. 常规动作 J3 建议留在 **[40°, 178°]** 内部（余量带）；接近边界必须主人确认
3. 多轴同时大角度运动：先给主人看目标数组，确认后才发
4. 所有运动命令必须经 `dummyarm_link` 限位检查（`check_limits=True`）
5. 意外行为第一反应：`!STOP`（急停锁位+清FIFO+失能），再诊断
6. 非测试时段：机械臂失能 + 停在 REST (0,-73,180,0,0,0)
7. 使能时人不在旁/不在看：不允许
8. 若需重新标定：按固件 `!CALIBRATION` 流程（L 位手动摆姿 → 回中 → 重启），
   期间 J3 手动摆动须极其缓慢并避开 35° 以下
9. **动作前先回 `!HOME`（7 字姿态 (0,0,90,0,0,0)），再开始执行动作**；动作结束回 REST + 失能
   （主人规定，2026-09-10；`dummyarm home` = 低速 10、阻塞到完成）

> 注（2026-09-10）：本节角度均为**物理/固件角**（安全底线以此为准）。模型角为
> `q_model = SIGNS·(q_fw + TH_HOME)`（TH=[0,−90,0,0,0,0]）：J3 物理 [35°,180°] = 模型 [−180°,−35°]，
> J2 物理 [−73°,90°] = 模型 [0°,163°]；REST 模型值 (0,163,−180,0,0,0)。

## 4. 固件版本事实（2026-09-08 测定）

- 刷机固件 = **auk/原版参数版**（DH 0.109/0.035/0.146/0.115/0.052/0.072；
  J2 -73..90；J3 35..180；J5 ±120；减速 30/30/30/24/30/50）

## 5. 末端执行器相关事故（2026-11-01，两次）

### 5.1 事故A：J2 收缩 + J5 翻转，末端扫向车架

用"只约束位置"的 IK（`solve_exact_tool0_ik`）横移 10cm 时，
IK 为了让 TCP 到位把 J2 从直立位收缩、并把 J5 从 −74° 翻到 +0.18°，
153mm 长、最大外廓 172mm 的锥形末端整体扫过，圆形开口转向车架。
人工断电止损，未损坏。

**对策**（已实现）：
- `scripts/arm_safety.py`：末端解析体积 + 车体包围盒 + 24 步 slerp 扫掠检查
- 判据是"侵入深度不得比起点更深"（允许逃开，禁止靠近）
- 所有定位改用**保持当前姿态**的位姿 IK（`solve_pose_ik`，约束工具 Z 轴）

### 5.2 事故B：用 J6 做滚转，等于执行了一次剪切

为把出料口从"朝天"转到"朝下"，下发 6 步 ×30° 的滚转。
IK 每步从零重解，跳到等价解分支：J4 保持不动，**全部滚转压在 J6 上**
（−0.6° → −196°）。而 J6 是刀片驱动轴，于是刀片被一路转到底 = 剪切。

**根因**：J6 同时承担"绕锥罩轴线滚转"与"刀片开合"，用 IK 动 J6 必然切果。

**对策（三道闸，已实现）**：
1. 规划层：`check_pose` / `arm_goto_xyz` 下发前强制 `fw[5] = 实测 J6`
2. 校验层：以"丢弃 J6 后的真实姿态"评估出料口偏离正下方角度，> 50° 拒绝
3. 通信层：`RefSerial.write` 若 `'>'` 指令中 J6 变化 > 0.3° 直接抛
   `J6Violation`，**指令根本发不出去**（`j6_locked=True` 默认）

**唯一豁免**：`do_cut()`，先校验 `|ΔJ6| ≤ 90°`，临时解锁，
`try/finally` 里无论成败立即重新上锁并以实测值为新基准。

### 5.3 末端执行器几何（STL 实测，`02_opResource/models/`）

| 件 | STL X | STL Y | STL Z |
|---|---|---|---|
| 法兰 | ±17.5 | ±30.5 | −8 → 0 |
| 外壳 | ±86.0 | −128 → 88 | −36 → 117 |
| 内层转子 | ±72.1 | ±73.0 | −10.4 → 123 |
| 上刀片 | −9.3 → 103.5 | ±102 | 123 → 128 |
| 下刀片 | −112.5 → 9.3 | ±107 | 118 → 123 |

- **tool0（法兰安装面 Z=−8）→ 罩口平面（Z=117）= 125mm**
- tool0 → 刀片外沿 = 136mm；罩口内径 ≈ Ø120；最大外廓 ≈ 172mm
- **出料口法向 = −Y_tool**（外壳 Y 多出 −128 那一片是出料槽侧壁）
- 出料口朝下 ⇔ `Y_tool.z > 0`；`port_down_deg()==0` 为正中朝下

### 5.4 姿态纪律

- 锥罩瞄准用 **J5 俯仰**，允许大幅摆动
- **不允许**用 J6 做滚转（会切果）
- 滚转只能由 J1~J5 的组合产生；规划时若出料口偏天 > 50° 该解作废

## 6. 事故C：伸展状态下失能，重力下坠撞地（2026-11-01 夜）

### 经过

一次完整套果+剪切成功后执行归位，`arm_goto_xyz --rest --speed 8` 的目标是
J2 走 75°、J4 走 95°（合计 150°+）。脚本用的是**固定 90 秒超时**，
慢速下这次移动**没有被等完**，于是被判"未到位"（报告 247.7mm 偏差）。
随后脚本继续执行 `disable.py`，机械臂在**伸展悬空**姿态失去力矩 →
重力下坠 → **撞地**。

### 三重错误

1. **速度选太慢**（`--speed 8` 走 150°），
2. **超时固定 90s**，长行程必然误判，
3. **失败后失能** —— 这是最致命的一条。

### 硬性规则（此后必须遵守）

> **任何状态下的执行出现问题，一律"锁轴"（保持力矩），绝不失能。**
> 失能只允许发生在**已确认停在 REST**之后。

### 已落地

- `arm_goto_xyz.hold_position()`：把实测位姿回发，原地保持力矩
- `arm_goto_xyz`：超时按"最大单轴行程 / 速度"动态估算；
  未到位时**锁轴并返回 1**，不再有任何失能路径
- `disable.py`：失能前读关节角，**与 REST 偏差 > 8° 直接拒绝失能**，
  改为锁轴保持（`--force` 可强制，但不应使用）
- 归位/收纳脚本同理，`safe_park_and_exit.sh` 走 `disable.py` 自动获得保护

### 教训

机械臂是**欠驱动重力负载**：失去力矩 ≠ 停止，而是"自由落体"。
"急停"在这台设备上必须理解为**保持力矩**，不是断电。

## 7. 事故D：21 V 直供 + 通电拔插 5521，计算板损坏（2026-11 记录）

### 经过

整机集成完成后，用牧田 15 Ah 5S（21 V）单轨直供：`5525 → REF 机械臂`、
`5521 → VENTUNO Q DC-IN`，两负载共用一根正极与一根负极。
在板子**通电、系统运行**的情况下拔插了 5521 DC 接口。
此后板子通电但无法正常工作，Linux 侧全栈停摆
（底盘 3 路 PWM 由板载 STM32H5 生成，也随板一起失效）。

### 为什么"在规格内"仍然会坏

- VENTUNO Q 的 DC 输入规格是 **7–24 V**，21 V 在范围内；
- 板载并非没有保护：DC 输入有 **SMBJ24CA 双向 TVS**、反接/反流功率开关、
  输入电流监测（INA232）、buck 软启动；
- 但仍然有四条失效链，**任一条成立即可损坏**：

| # | 机制 |
|---|---|
| ① | 5521 是"中心针先通、外筒先断"的结构，拔插瞬间**回流路径先断**，板上电流改走 USB 地 / 信号地 / 内部 ESD 二极管——**这条路径在输入 TVS 的保护范围之外** |
| ② | 21 V 工作时距 TVS 站压 24 V 只剩 **3 V 余量**，插头弹跳 + 线束电感 + 470 µF 的振铃更易越过钳位点 |
| ③ | 与机械臂共用负极：步进 4.9 A/轴换相产生的地弹与母线尖峰长期作用在板端输入级 |
| ④ | 单一总开关、两负载同轨：关电 = 臂失力下坠；开电 = 两路电容同时抢充电 |

- Arduino 官方原文亦警告：*"Avoid connecting or disconnecting DC sources while the
  board is under heavy load."* —— 电源 OR 切换会产生瞬态，轻则复位、重则损坏。

### 硬性规则（新增，优先级等同 J3 红线）

1. **禁止通电拔插任何 DC 接口**；插拔前先断总开关，等 10 s。
2. **计算板不再吃 21 V**：Buck 降到 12 V，或改用板载**螺丝端子**（7–24 V / 10 A）
   或 USB-C PD（9–20 V / 3 A）。
3. **机械臂与计算板必须独立支路**：各自保险 + 各自开关，不共用插头。
4. **换新板之前**必须完成示波器验收（臂启停 / 插拔瞬间的尖峰与地弹），
   见 [`POWER_v2_SPEC.md`](POWER_v2_SPEC.md) §7。
5. 断电顺序固定：`safe_park_and_exit.sh` → 断臂 → `shutdown` → 总开关。

### 教训

**"符合输入规格"不等于"能扛住这个系统的电气环境"。**
单轨直供把两个负载的故障耦合在一起：任何一个动作（拔插、电机换相、开关抖动）
都会同时作用在两个负载上。防御要按**失效链**做，不要按"单个器件是否合规"做。
